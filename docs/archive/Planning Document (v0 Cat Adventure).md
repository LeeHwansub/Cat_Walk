# CAT ADVENTURE

## 통합 프로젝트 기획서 및 Claude 개발 지시서

**프로젝트명:** Cat Adventure (고양이의 모험)  
**프로젝트 유형:** 브라우저 기반 3D 힐링 콘텐츠  
**개발 목표:** 1일 내 작동하는 MVP 프로토타입 제작  
**개발 담당:** Claude AI  
**최종 목표:** 사용자가 접속하지 않아도 고양이가 자신만의 하루를 살아가는 작은 가상 세계 구현

---

# 1\. 프로젝트 개요

## 1.1 프로젝트 소개

Cat Adventure는 사용자가 자신만의 고양이를 만들고, 작은 가상 세계에서 고양이가 자유롭게 생활하는 모습을 관찰하거나 직접 조작할 수 있는 브라우저 기반 힐링 콘텐츠다.

일반적인 게임처럼 미션을 수행하거나 목표를 달성하는 것이 핵심이 아니다.

사용자는 고양이가 주변을 탐험하고, 풀밭에서 뒹굴고, 그루밍을 하고, 낮잠을 자는 모습을 감상한다.

필요할 때는 직접 고양이를 조작할 수 있지만, 기본적으로는 고양이가 자율적으로 행동한다.

## 1.2 핵심 콘셉트

> 내가 접속하지 않아도 고양이는 자기만의 하루를 살아간다.

핵심 가치는 다음과 같다.

- 귀여움: 바라보는 것만으로도 즐거운 고양이
- 자유로움: 정해진 미션 없이 자유롭게 탐험
- 편안함: 조작하지 않아도 자연스럽게 움직이는 고양이
- 개성: 사용자가 직접 만든 자신만의 고양이
- 몰입감: 시간, 날씨, 소리, 환경에 따라 달라지는 작은 세계

## 1.3 가장 중요한 제품 방향

이 프로젝트는 생존 게임이나 일반적인 RPG가 아니다.

- 사용자를 지속적으로 조작에 참여시키지 않는다.
- 배고픔이나 컨디션을 이유로 사용자를 압박하지 않는다.
- 고양이가 스스로 행동하는 모습을 핵심 경험으로 만든다.
- 화려한 기능보다 자연스러운 움직임과 분위기를 우선한다.
- 기능을 많이 넣는 것보다 적은 기능이라도 완성도 있게 구현한다.

# 2\. 핵심 사용자 경험

사용자가 서비스를 처음 접속했을 때의 흐름은 다음과 같다.

1. 시작 화면에서 Cat Adventure에 진입한다.
2. 자신이 원하는 고양이를 생성한다.
3. 고양이의 외형과 기본 설정을 선택한다.
4. 작은 마을이나 숲속 공간에 입장한다.
5. 고양이가 자율적으로 움직이는 모습을 감상한다.
6. 필요하면 직접 조작하거나 카메라를 변경한다.
7. 먹이를 주거나 주변 환경과 상호작용한다.
8. 고양이가 그루밍하거나 낮잠을 자는 모습을 관찰한다.
9. 설정에서 소리와 화면을 조절한다.
10. 다음 접속에서도 이전 설정과 고양이를 불러온다.

사용자가 아무것도 하지 않고 바라보기만 해도 콘텐츠가 성립해야 한다.

## 3.1 기본 외형 설정

설정 가능한 항목:

- 성장 단계: 새끼 / 성체
- 크기
- 기본 털 색상
- 무늬
- 눈 색상
- 눈 모양
- 꼬리 색상

## 3.2 무늬 종류

기본 제공 무늬:

- 기본 단색
- 턱시도
- 치즈
- 고등어
- 삼색

색상과 무늬는 서로 조합할 수 있도록 설계한다.

## 3.3 사진 기반 커스터마이징

후속 업데이트 기능이다.

사용자가 실제 고양이 사진을 업로드하면 AI가 외형을 분석하여 가상 고양이의 외형에 반영한다.

분석 대상:

- 털 색상
- 무늬
- 눈 색상
- 얼굴 형태
- 귀 모양
- 꼬리 특징

사진 분석 결과를 사용자가 직접 수정할 수 있어야 한다.

외부 AI API가 필요하므로 MVP에서는 구현하지 않는다.

# 4\. 플레이 방식

## 4.1 혼합형 플레이 방식

최종 플레이 방식은 혼합형으로 확정한다.

평소에는 고양이가 자동으로 생활하고, 필요할 때 사용자가 직접 조작한다.

### 자동 생활 모드

- 고양이가 스스로 이동한다.
- 주변 환경을 탐색한다.
- 다양한 자율 행동을 수행한다.
- 주변 NPC나 사물과 상호작용한다.
- 사용자는 자유롭게 관찰한다.

### 직접 조작 모드

- WASD 또는 방향키로 이동한다.
- 사용자가 원하는 방향으로 고양이를 움직인다.
- 조작 종료 후 자동 생활 모드로 자연스럽게 복귀한다.

### 관찰 모드

- 고양이를 중심으로 카메라를 자유롭게 조작한다.
- 고양이의 행동을 감상한다.
- 풍경을 감상한다.
- 고양이 시점으로 주변을 바라본다.

모드가 전환될 때 고양이의 위치나 행동이 갑자기 끊기지 않아야 한다.

# 5\. 자율 행동 시스템

이 프로젝트에서 가장 중요한 기능 중 하나다.

고양이가 사용자의 입력 없이도 자연스럽게 행동해야 한다.

## 5.1 기본 행동

MVP에서 우선 구현할 행동:

- 걷기
- 앉기
- 주변 바라보기
- 냄새 맡기
- 앞발을 핥는 그루밍
- 얼굴을 닦는 그루밍
- 낮잠 자기
- 꼬리 흔들기

## 5.2 그루밍 시스템

고양이가 스스로 몸을 정리하는 자연스러운 행동이다.

그루밍은 단순한 애니메이션이 아니라 고양이의 일상적인 생활 행동 중 하나로 취급한다.

### 그루밍 행동 종류

1. 앞발 핥기
   - 고양이가 앞발을 들어 핥는다.
   - 몇 차례 핥은 뒤 앞발을 내린다.
2. 얼굴 닦기
   - 앞발을 핥은 뒤 얼굴 주변을 문지른다.
   - 눈과 볼 주변을 닦는 듯한 동작을 표현한다.
3. 몸통 그루밍
   - 몸을 살짝 구부리고 옆구리나 몸통을 핥는다.
   - 자연스러운 자세 변화가 중요하다.
4. 털 정리
   - 몸의 특정 부위를 핥거나 정리하는 행동을 표현한다.
5. 그루밍 후 휴식
   - 그루밍을 마친 뒤 앉거나 편안하게 휴식한다.

### 그루밍 실행 조건

- 일정 시간 활동한 뒤 휴식 중일 때
- 앉아서 주변을 바라보는 중일 때
- 낮잠을 자기 전이나 후
- 별다른 상호작용이 없을 때
- 고양이의 자율 행동 선택 결과에 따라

그루밍이 지나치게 자주 반복되지 않도록 확률과 대기 시간을 조절한다.

### 그루밍 UX 원칙

- 사용자가 직접 실행하지 않아도 된다.
- 강제적으로 그루밍을 시키지 않는다.
- 청결도 수치를 도입하지 않는다.
- 그루밍을 하지 않아도 불이익이 없다.
- 그루밍 도중 사용자가 직접 조작하면 자연스럽게 행동을 종료한다.
- 고양이의 자세와 애니메이션이 부드럽게 연결되어야 한다.

## 5.3 확장 행동

후속 업데이트에서 구현할 행동:

- 풀밭에서 뒹굴기
- 나비나 벌레 쫓기
- 물 마시기
- 상자 안에 들어가기
- NPC에게 다가가기
- 다른 고양이와 상호작용하기
- 햇빛이 드는 곳에서 낮잠 자기

## 5.4 자율 행동 로직

단순히 일정 시간마다 애니메이션을 무작위로 실행하는 방식은 피한다.

주변 환경과 상황에 따라 행동이 달라져야 한다.

예시:

- 주변에 풀밭이 있으면 풀밭에서 뒹굴 수 있다.
- 주변에 물이 있으면 물을 마실 수 있다.
- 일정 시간 이동하면 앉아서 휴식할 수 있다.
- 주변에 흥미로운 사물이 있으면 다가가서 냄새를 맡는다.
- 밤이 되면 휴식이나 수면 행동의 확률이 높아진다.
- 활동 후 휴식 중에는 그루밍을 할 수 있다.

구현 시 다음 사항을 고려한다.

- 행동별 실행 확률
- 행동 실행 조건
- 행동 지속 시간
- 행동 사이의 대기 시간
- 동일 행동 반복 방지
- 주변 장애물 및 이동 가능 영역
- 현재 행동의 자연스러운 종료

고양이가 지나치게 바쁘게 움직이지 않도록 한다.

행동하지 않고 가만히 있는 시간도 중요하다.

# 6\. 맵 및 환경

## 6.1 기본 맵

MVP에서는 작은 마을과 숲을 중심으로 구현한다.

### 마을

- 작은 집
- 골목길
- 나무와 풀
- 벤치
- 사람 NPC
- 먹이를 제공하는 공간

### 숲

- 나무
- 풀밭
- 꽃
- 작은 연못
- 나비와 벌레
- 산책로

맵의 규모를 무리하게 키우지 않는다.

작은 공간이라도 자연스럽게 탐험할 수 있도록 구성한다.

## 6.2 후속 맵

추가할 수 있는 맵:

1. 바닷가
   - 모래사장
   - 파도
   - 해변에서 낮잠
2. 고양이 쉼터
   - 쿠션
   - 상자
   - 다른 고양이
   - 휴식 공간
3. 폐건물
   - 오래된 건물
   - 빛과 그림자
   - 탐험 요소
4. 지하 하수도
   - 어두운 공간
   - 물웅덩이
   - 좁은 통로
   - 조명 효과

이 맵들은 MVP 범위에 포함하지 않는다.

# 8\. 배고픔 및 먹이 시스템

## 8.1 배고픔

고양이가 활동하면 배고픔 수치가 천천히 감소한다.

먹이를 먹으면 배고픔이 회복된다.

## 8.2 먹이 제공

- 맵에 먹이를 배치할 수 있다.
- 사람 NPC가 먹이를 제공할 수 있다.
- 먹이를 먹는 간단한 애니메이션을 제공한다.

## 8.3 반드시 지켜야 할 UX

배고픔은 힐링 경험을 보조하는 요소이지 생존 압박 요소가 아니다.

- 배고픔이 0이 되어도 죽지 않는다.
- 배고픔이 낮아도 탐험을 제한하지 않는다.
- 배고픔 때문에 사용자를 강제로 조작하게 만들지 않는다.
- 먹이를 주는 행동은 선택 사항이다.

# 10\. 사운드 시스템

## 10.1 기본 사운드

MVP 구현 대상:

- 기본 야옹 소리 2\~3종
- 골골송 1종
- 자연 배경음
- 간단한 환경 효과음

## 10.2 상황별 울음소리

- NPC를 만났을 때 짧은 야옹
- 먹이를 발견했을 때 기대하는 울음
- 쓰다듬을 때 골골송
- 탐험 중 가끔 짧은 야옹
- 잠들기 전 작은 울음

울음소리가 너무 자주 반복되지 않도록 한다.

같은 소리의 연속 재생을 방지한다.

## 10.3 사운드 설정

- 전체 사운드 음소거
- 고양이 울음소리 ON/OFF
- 자연 배경음 ON/OFF
- 환경 효과음 ON/OFF
- 사운드별 볼륨

MVP에서는 전체 음소거와 고양이 울음소리 음소거를 우선한다.

## 10.4 고양이별 울음소리 성격 시스템

후속 업데이트 기능이다.

모든 고양이가 똑같이 울지 않도록 고양이마다 고유한 울음소리 성격을 부여한다.

| 성격 | 울음 특징 |
| --- | --- |
| 조용한 고양이 | 울음 빈도가 낮고 작은 소리 |
| 애교 많은 고양이 | 자주 야옹하고 골골송을 많이 사용 |
| 호기심 많은 고양이 | 새로운 사물을 발견하면 울음 |
| 도도한 고양이 | 필요한 순간에만 짧게 울음 |
| 수다쟁이 고양이 | 탐험 중 다양한 울음소리 사용 |

추가 설정 요소:

- 기본 음높이
- 울음소리 음색
- 울음 빈도
- 울음 길이
- 상황별 울음 반응
- 골골송 빈도

고양이별 성격은 행동과 상호작용에도 영향을 줄 수 있도록 확장 가능성을 고려한다.

MVP에서는 공통 사운드 시스템만 구현한다.

# 11\. 저장 시스템

MVP에서는 브라우저 로컬 저장을 우선한다.

저장 대상:

- 고양이 외형 설정
- 고양이 기본 설정
- 사운드 설정
- 사용자 설정
- 필요한 최소한의 플레이 상태

브라우저를 새로고침해도 설정이 유지되어야 한다.

## 13.1 기술 선정 기준

1. 브라우저에서 실행 가능해야 한다.

4. 캐릭터 이동 및 애니메이션 구현이 가능해야 한다.
5. 개발 시간이 짧아야 한다.
6. 외부 서비스 의존도를 최소화해야 한다.
7. 추후 기능 확장이 가능해야 한다.

1일 MVP에서는 모든 3D 모델을 직접 제작하지 않는다.

사용 가능한 무료 에셋을 적극적으로 검토한다.

다음 조건을 확인한다.

- 상업적 이용 가능 여부
- 라이선스
- 출처 표시 의무
- 수정 및 재배포 조건

저작권이 불명확한 에셋은 사용하지 않는다.

고양이 모델은 우선 기본 모델을 활용하고, 외형 커스터마이징은 가능한 범위에서 적용한다.

# 19\. 최종 개발 방향

이 프로젝트에서 가장 중요한 것은 고양이가 살아 있는 것처럼 느껴지는 경험이다.

고양이가 계속 움직이거나 사용자의 명령에만 반응하는 방식이 아니라, 가끔은 멈춰서 주변을 바라보고, 앞발을 핥아 얼굴을 닦고, 풀밭에서 쉬고, 낮잠을 자는 자연스러운 모습을 만들어야 한다.

사용자가 접속했을 때 고양이가 자신만의 생활을 이어가고 있다는 느낌을 주는 것이 핵심이다.

**우선순위는 다음과 같다.**

1. 자연스러운 고양이 움직임
2. 편안한 환경과 분위기
3. 자동 생활과 직접 조작의 조화
4. 자신만의 고양이 생성
5. 그루밍 등 일상 행동의 자연스러운 표현
6. 사운드와 환경 상호작용
7. 추후 콘텐츠 확장

기능의 개수보다 핵심 경험의 완성도를 우선한다.

최종적으로 브라우저에서 직접 실행하고 확인할 수 있는 작동 가능한 프로토타입을 완성한다.
