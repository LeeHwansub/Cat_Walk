## 2. 작업 내용

### 2-1. 건물 디테일 (지시서 2번): 모듈형 부품

부품은 모두 코드로 만든다. 텍스처는 캔버스로 생성하므로 외부 에셋이나 라이선스 문제가 없다. 부품마다 `만들기(위치, 크기, 변형값) → { 메시, 충돌, 관심 지점 }`을 돌려주는 함수로 만들어, 어느 구역에서든 다시 쓸 수 있게 한다.

| 부품 | 내용 |
|---|---|
| 필로티 빌라 | 1층은 기둥과 천장만 있는 주차 공간, 2층부터 빌라. 천장 높이는 약 2.4m (추정) |
| 에어컨 실외기 | 벽걸이형(앵글 받침)과 바닥형. 팬 그릴. 고양이가 냄새를 맡는 관심 지점 |
| 전봇대와 전선 | 이미 있는 전봇대를 부품으로 옮기고, 전봇대 사이에 처진 전선(곡선)과 변압기를 더한다 |
| 담벼락 | 블록 담과 시멘트 담, 위에 기와나 철망 변형. 대문 |
| 우편함 | 빌라 입구의 집합 우편함, 주택 대문의 개별 우편함 |
| 계단 | 빌라 외부 계단과 난간. 고양이가 올라가지는 않고 장식과 충돌만 둔다 (계단 오르기는 범위 밖) |
| 창틀·방범창 | 튀어나온 창틀, 방범창 격자, 일부 창에 화분 |
| 난간 | 옥상과 계단 난간 |
| 낡은 디테일 | 벽 얼룩(빗물 자국, 이끼, 갈라짐)을 텍스처에 섞고, 건물마다 다르게 |
| 화분 | 이미 있는 화분을 부품으로 옮기고, 스티로폼 상자 텃밭을 추가한다 |

### 2-2. 고양이 이동 경로 (지시서 3번): 차 밑, 필로티 밑

**낮은 공간 충돌.** 충돌 정보에 천장 높이가 있는 영역(`LowSpace { 영역, 천장 높이 }`)을 추가한다.
- 고양이가 몸을 최대로 낮췄을 때의 높이가 천장보다 낮으면 통과하고, 아니면 막힌다. 크기와 체형에 따라 달라진다. 통통한 대형 고양이는 못 들어갈 수 있다.
- 차는 차체를 낮은 공간으로, 바퀴 4개를 막힌 원으로 바꾼다. 지금 코드의 차체 바닥 높이는 0.27m다.
- 평상(높이 0.38m) 밑, 놀이터 미끄럼틀 밑도 같은 방식으로 들어갈 수 있게 한다.
- 필로티 밑은 천장이 높아서 기어갈 필요가 없다. 기둥만 막고, 천장 높이는 카메라 제한에만 쓴다.

**기어가기 자세.** 자세 값에 `crawl`(0~1)을 추가한다.
- 다리를 굽히고 몸과 머리를 낮춘다. 꼬리는 낮게 수평으로 두고, 걸음은 짧고 느리게(약 60%, 추정) 한다.
- 머리 위 천장 높이에서 연속으로 계산하므로, 들어가고 나올 때 자연스럽게 바뀐다.
- 1단계 6번(앉은 채로 걷기 금지)과는 다른 의도된 걷기 동작이다. 그래서 이동 차단 조건에는 넣지 않는다.
- 낮은 공간 안에서는 앉기, 아저씨 앉기, 기지개, 그루밍처럼 높이가 필요한 행동을 하지 않는다. 식빵, 낮잠, 꼬리 감고 엎드리기만 한다. 쓰다듬기 반응도 앉지 않고 엎드린 채 골골송만 한다.
- 풍선 고양이(떠 있는 상태)는 낮은 공간에 들어가지 못한다. 필로티 밑에서는 뜨는 높이를 천장 아래로 제한한다.

**카메라.**
- 낮은 공간에서는 따라가는 카메라를 가깝고 낮게 자동 조정한다 (거리 약 0.6배, 추정). 나오면 원래대로 돌아간다.
- 카메라 높이가 천장 높이(필로티)나 차체를 넘지 않게 제한한다.
- 화면 레이캐스트용으로 실제 메시 대신 단순한 상자를 따로 둔다. 바퀴 사이 같은 빈틈에서 오판정이 줄고 비용도 줄어든다.
- 확인 기준: 테스트 경로 전체에서 카메라 위치가 차체나 천장 상자 안에 들어가는 프레임이 0이어야 한다.
- 캣캠(1인칭)은 눈 위치가 같이 낮아지므로 그대로 쓴다.

**자율 행동 "차 밑에 숨어 쉬기"(`hideUnderCar`).**
- 흐름: 차 옆 입구 지점까지 걷기 → 기어 들어가기 → 차 밑에서 식빵이나 낮잠(15~30초) → 기어 나오기.
- 근처에 차가 있을 때만 고른다. 가중치는 낮게(0.2), 지쳤을 때는 조금 높게, 쿨다운은 120초로 한다 (모두 추정값, 조정 가능).
- 길찾기가 없으므로 차마다 입구 지점(긴 쪽 옆)을 미리 정해 두고, 거기서 곧장 들어간다.

### 2-3. 맵 확장 (지시서 4번): 구역 단위 연결

**구역.** 골목 → 필로티 주차장 → 놀이터 → 공원·숲 순서로 잇는다. 배치 방식은 6장 D-31에서 정한다.

| 구역 | 내용 |
|---|---|
| 골목 | 지금 골목에 2-1 부품을 더한다 (전선, 실외기, 우편함, 창틀, 얼룩 등) |
| 필로티 주차장 (새로) | 필로티 빌라 2~3동, 기둥 사이 주차된 차, 실외기, 분리수거장, 그늘 |
| 놀이터 (새로) | 미끄럼틀, 그네, 시소, 모래밭, 벤치, 우레탄 바닥. 미끄럼틀 밑은 낮은 공간이다 |
| 공원·숲 | 지금 공원에 숲(나무가 빽빽한 구역, 오솔길, 덤불, 낙엽)을 잇는다 |

**구역 사이 연결.** 로딩 화면 없이 걸어서 이어진다 (권장, D-32). 연결부는 좁은 통로(담 사이 길, 대문, 오솔길)로 만들어 먼 구역이 한눈에 보이지 않게 한다.

**가까운 구역만 그리기.** 지금은 모든 맵을 코드로 만들기 때문에 내려받을 파일이 없다. 그래서 "불러오기"는 "만들어서 그리기"를 뜻한다. 방식은 D-33에서 정한다.
- 충돌 정보는 가벼우므로 모든 구역을 항상 둔다. 다만 구역별로 나눠 둬서 가까운 구역만 검사한다.
- 정적인 물체는 구역마다 재질별로 합친다 (`BufferGeometryUtils.mergeGeometries`). 같은 부품이 반복되면 `InstancedMesh`로 그린다. 목표는 골목 구역의 그리기 호출을 490회에서 약 150회 이하로 줄이는 것이다 (목표치이며 측정 전 추정).
- 그림자는 가까운 구역의 물체만 드리운다.

**자율 이동과 구역.** 자율 모드에서는 지금 구역 안에서 주로 돌아다닌다. 가끔 연결 지점(웨이포인트)을 거쳐 이웃 구역으로 넘어간다. 맵 전체 길찾기는 만들지 않는다.

## 5. 검증 방법
- **단위 테스트:**
  - 낮은 공간: 크기와 체형별 통과·차단, 천장 높이 조회
  - `crawl` 값: 천장 높이에 따른 변화, 이동 차단 조건에 들어가지 않는지
  - 카메라: 천장 제한 함수와 테스트 경로의 차체 침범 0프레임
  - 구역: 거리별 보이기, 경계 근처에서 깜빡임(왔다 갔다) 방지
  - `hideUnderCar`: 고르는 조건, 쿨다운, 낮은 공간 안의 행동 제한
- **타입 검사, 빌드.**
- **브라우저 (headless Chrome):**
  - 구역별 캡처
  - 차 밑 기어가기 측면·카메라 캡처
  - 필로티 밑 카메라 높이 값
  - `renderer.info`의 그리기 호출과 삼각형 수
  - 소프트웨어 렌더링이라 프레임 시간은 상대값으로만 본다
- **사용자 확인:** 실제 PC와 휴대폰에서 구역을 넘어갈 때 끊김이 있는지, 프레임이 어떤지 (테스트 안내에 항목 추가).

## 6. 결정이 필요한 항목

| 번호 | 항목 | 선택지 | 권장 |
|---|---|---|---|
| D-31 | 구역 배치 | **A.** 공원을 동쪽으로 옮기고, 골목과 공원 사이에 필로티 주차장과 놀이터를 넣는다. 지시서 순서대로 한 줄로 이어지고, 맵 길이는 약 50m → 110m가 된다 (추정). 저장 위치가 공원이었다면 시작 위치로 돌아간다 / **B.** 지금 골목과 공원은 그대로 두고, 새 구역을 남북으로 덧붙인다. 기존 좌표가 유지되지만 순서는 지시서와 다르다 | A |

## 7. 별도 승인 항목
- **아키텍처 변경:** `neighborhood.ts`를 부품(`world/parts`)과 구역(`world/zones`)으로 나누고, 충돌 구조에 높이(낮은 공간)를 더한다. 기존 코드를 옮기는 것이지 동작을 바꾸지는 않는다 (3-0).
- **의존성:** 추가하지 않는다. 합치기 도구 `BufferGeometryUtils`는 이미 설치된 three 패키지 안에 있다 (`three/examples/jsm/utils/BufferGeometryUtils.js` 확인).
- **외부 에셋:** 쓰지 않는다. 모두 코드와 캔버스 텍스처로 만든다. 실사 텍스처(CC0 등)를 쓰고 싶다면 따로 조사하고 승인받는다.
- commit, push는 작업마다 따로 승인받는다.

## 8. 위험과 대응
- **길찾기가 없어 자율 이동이 구석에 끼임:** 구역 안에서만 목표를 고르고, 구역 사이는 웨이포인트로 넘어간다. 오래 못 움직이면 다른 목표를 고른다.
- **맵이 커져 성능이 떨어짐:** 3-0에서 그리기 호출을 먼저 줄이고, 3-4에서 구역 단위로 관리한다. 측정은 소프트웨어 렌더링이라 실제 기기 확인이 필요하다.
- **기어가기 자세의 이음새:** 도형 모델이라 다리를 많이 굽히면 관절 이음새가 보일 수 있다. 털이 일부 가려 준다 (D-29 이후 같은 한계).
- **3-0 정리 중 화면이 바뀜:** 같은 시드로 정리 전후 캡처를 비교한다.
- **범위 밖으로 둔 것:** 계단과 담 위 오르기(점프), 실내, 밤 조명, 아파트 단지. 필요하면 따로 제안한다.
